# DSH Dots 1.0.12-review.1 — 登录保持设置 / Login Retention

> 2026-11-09 · 审查候选（未发布正式 GitHub Release）

## 本轮实现

用户在 DSH **设置 → Dots 登录保持** 中手动检查、应用、恢复浏览器持久化修改。原 Dots 主页面、预加载、切换保留、刷新、浏览器登录流程及主题设计保留。

- 插件 Host 利用 DSH 已有的认证连接暴露三个设置操作：`status`、`apply`、`restore`，无额外监听端口。
- 修复器定位 DSH Desktop 的 `resources/app.asar`，解析真实 ASAR 头及 `lib/main.js`，匹配 `DesktopBrowserGuests` 的分区分配逻辑，仅对 `dsh-dots:personal-browser` 选择 `persist:dsh-dots-personal-browser`，原分区策略保留于其他工作区。
- Electron Node 环境使用 `original-fs` 读取和修改真实 ASAR，而非将 ASAR 当作虚拟目录。
- 应用前保留按原版 SHA-256 命名的完整归档备份；重算主模块的校验块和关联文件偏移；生成新归档、校验后替换；恢复时匹配当前补丁版本对应的完整原版备份。
- Windows 文件被宿主占用时，使用一次性、由原 DSH Host IPC 断开触发的延后替换；无常驻定时监测。完成时移除临时归档及请求记录。
- 不读取 ChatGPT Cookie、Token、浏览器目录和用户资料。没有增加 MCP 或修改其他 DSH 浏览器设置。

## 用户操作

安装候选 TGZ 后，在 DSH Desktop 设置中打开 **Dots 登录保持**。状态为“等待应用”时点击“一键应用”；若显示“已安排”，先完全退出 DSH（含托盘）再重新打开。完成后用官方 ChatGPT 网页正常登录；后续重启使用原生持久化分区。需要撤销时点击“恢复原版”并重启 DSH。DSH 更新覆盖 `app.asar` 后可重新检查并应用。

## 适配与真实条件

- **Windows**：目标为常规已安装 Desktop 的 `resources/app.asar`；一键修改及 Windows 文件占用延后应用路径已完成源码和受控归档测试。需要在真实 DSH 0.2.2-rc.1 Windows 安装包上完成点按、退出、重启及官网登录态保留的实机验收。
- **Linux**：共享 Node 归档处理核心。常规可写安装目录可以修改；官方 AppImage 可能处于只读挂载，需要对该打包形式采用合适的写入途径。Linux 桌面安装未实机验证。
- **macOS**：共享 ASAR 解析与修改核心，并支持应用包的 `Contents/Resources/app.asar` 路径。官方签名应用的安装包资源受签名完整性保护，直接改写将使签名无效，修复器会识别并保留原文件；正式支持需要针对签名安装包落实有效途径。macOS 实机未验证。
- **DSH 版本**：无硬编码宿主版本锁。实际执行前验证目标归档及浏览器分区代码形态；未来宿主更改时，需要根据新源码适配。

## 验证记录（隔离 Node 22.16.0 / Linux 容器）

- `npm test`：44 项测试，其中 40 通过、4 项由于未挂载 DSH 全量源码而跳过；包含原有 UI／主页面回归、设置页操作及认证 RPC、模拟 ASAR 备份／修改／恢复、文件哈希、退出 IPC 一次性应用、已更新文件拒绝旧版替换。
- `npm run pack:check`：14 项预定生产文件的白名单及入口检查通过。
- ASAR 原版和修改后的字节差异仅涉及 `lib/main.js`、完整性元数据、相应偏移和归档目录头；其他载荷字节保持原样。
- 尚未把本候选应用到用户正在运行的 DSH 安装，不包含用户真实 Cookie。

## 审查重点

核对真实 `dsh-v0.2.2-rc.1` 发布安装包中编译后的 `DesktopBrowserGuests` 目标字符串；核实 Windows 打开中的 `app.asar` 替换/延后替换、应用启动完整性、实际网页登录和 DSH 重启后状态；针对 macOS 已签名应用和 Linux AppImage 决定适用的交付路径。

源码修改、相关测试及校验清单包含于审查包；该版本尚未发布 GitHub Release 或提交市场。
