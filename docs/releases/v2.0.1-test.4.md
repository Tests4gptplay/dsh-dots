# DSH Dots 2.0.1-test.4：MCP 持续订阅与元数据精简

[返回 README](../../README.md) · [上一测试版](v2.0.1-test.3.md)

## 本次更新

- 新增 `dsh_api_subscribe`，接通 DSH `typertGateway.stream()` 原生异步事件流。DSH 连续产生的事件通过当前 MCP `tools/call` 的 `notifications/progress` 连续送出，包含完整 JSON 数据。
- 订阅由 MCP 请求持有；客户端断开或取消请求时，将取消信号传递给 DSH Gateway 并关闭本次迭代器。DSH 原生流自行结束时返回已发送事件数。
- `dsh_api_snapshot` 保留，适合只需要获取第一条状态的调用。
- 只对能够确认是纯查询的工具声明 `readOnlyHint: true`；通用 API、通用工具调用与其他未知具体效果的操作不再由 Dots 统一贴上“破坏性／开放网络”等风险标签。
- MCP 本地连接、DSH 原生权限与执行器、官方 Tunnel Client 管理沿用既有设计；不增加额外任务校验、审查、轮询或事件数量上限。

## 调用方式

在 DSH 插件安装页使用：

```text
github:Tests4gptplay/dsh-dots#2.0.1-test.4
```

MCP 客户端连接成功后，可调用：

```json
{
  "name": "dsh_api_subscribe",
  "arguments": {
    "namespace": "workspace",
    "method": "follow",
    "args": {}
  }
}
```

MCP 客户端在请求的 `_meta.progressToken` 中提供进度标识（官方 SDK 支持 `onprogress` 回调），每收到一条 `notifications/progress` 即读取其 `params.message`，内容为一条原生 DSH 事件的 JSON。进度数字 `progress` 依照事件数量递增。主动取消 MCP 请求即结束该次订阅，不主动取消 DSH 已接受的会话任务。

**客户端支持说明：** 连续事件通知依赖 MCP 客户端支持进度通知及长连接。没有进度通知的客户端可以继续调用 `dsh_api_snapshot` 获取首条状态，或调用 `dsh_api_call` / DSH Session 工具查询当前信息。

## 验收

覆盖源码回归、2025 与 2026 两代 MCP HTTP 请求的连续 SSE 事件、客户端取消和原生迭代器释放、未提供 `progressToken` 时的明确结果，以及 DSH 原生 `workspace.follow` 入口。实际测试结果以该分支 GitHub Actions 记录为准。
