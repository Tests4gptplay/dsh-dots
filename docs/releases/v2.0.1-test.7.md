# DSH Dots 2.0.1-test.7：可选择的 Dot 主动通知

[返回项目介绍](../../README.md) · [上一测试版](v2.0.1-test.6.md)

## 新增能力

在 **DSH → 设置 → Dots → 主动通知 Dot** 中独立设置通知。首次安装 **默认关闭**；开启后，用户在设置页逐行填入允许通知的 Session ID，按需勾选「会话轮次结束」和「会话执行错误」，然后保存。

只有用户所选的会话与事件类型才可建立官方 MCP Events 订阅。Dot 创建订阅时提交 Webhook 回调地址和签名密钥；Dots 按官方协议验证回调、持久保存订阅，并在实际 DSH 事件发生时发送签名 HTTPS 事件。关闭开关会清除当前订阅，更换 MCP 连接密钥也会撤销先前的订阅授权。

通知事件只提供 Session ID、轮次与结束原因类型（或错误发生状态）；完整会话和工作区资料通过原有 MCP 工具按需读取。未选中的会话不会产生主动通知。

## 启用方法

1. 在 DSH 添加插件时输入：

   ```text
   github:Tests4gptplay/dsh-dots#2.0.1-test.7
   ```
2. 在 DSH 的 Dots 设置中启用现有 MCP Server；按需启用官方 Tunnel Client。
3. 打开 **主动通知 Dot**，填写需要通知的准确 Session ID，勾选事件类型，保存并启用。
4. 在 ChatGPT 的插件页面重新扫描该 MCP 服务器，使事件定义可被发现；向 Dot 明确说明要订阅哪个 Session ID、哪个事件，以及收到通知后的处理方式。
5. 不再需要时关闭主动通知开关。已建立的通知订阅会清除；MCP 工具连接仍可继续使用。

## 设计与实现

- DSH 原生入口：`session/event` 的 `turn/end`、`agent/error`。
- 官方事件方法：`events/list`、`events/subscribe`、`events/unsubscribe`。
- 官方回调：HTTPS，Standard Webhooks 签名、单次挑战验证、按订阅 ID 投递；订阅记录存储在当前 DSH profile 的 `dsh-dots/notifications.json`。
- 默认不注册主动推送；通知不附加独立的 DSH 内容审核、任务拦截或定时扫描。
- 原有请求内 `notifications/progress` 流仍然是单次 MCP 调用机制，与主动 Webhook 事件分开。

## 测试与发布阶段

自动回归测试检查默认关闭、精确会话与事件选择、签名验证、未选会话不投递、取消订阅、重启保存、密钥轮换撤销、用户设置 UI、原有工具/隧道及候选 TGZ 内容。Webhook 验收采用受控回调，真实 ChatGPT Dot 账户侧的回调注册与投递由用户连接后验证。

正式 Release、npm 和市场发布需由用户另行决定。
