# DSH Dots 2.0.2: Restoring the saved Tunnel connection

[Project README](../../README.en.md) · [中文](v2.0.2.md) · [Setup guide](../../README.en.md#connect-your-dot)

## What's new

DSH Dots 2.0.2 promotes `2.0.2-test.1`, verified on the user's Windows DSH installation. Once the MCP listener is available, Tunnel restoration reads the saved installation directory, executable and Tunnel ID from the current DSH profile and calls the same `start(settings)` implementation as the Settings button.

The client starts once, reuses an in-flight launch, and leaves an already-running instance in place. MCP remains responsive while the client starts; Settings receives the resulting runtime status. A user-selected Stop persists. Existing Runtime API Key persistence, login retention and MCP behavior are retained.

This version also preserves the confirmed Settings design, the expandable five-step setup guide, Back and clickable Dot home navigation, 17 MCP tool endpoints, and session-scoped proactive notifications.

## Install or update

In DSH **Plugins → Add plugin**, enter:

```text
github:Tests4gptplay/dsh-dots#v2.0.2
```

The saved Tunnel ID and client path remain in the DSH user profile. If startup reports `CONTROL_PLANE_API_KEY is empty`, re-enter your existing Runtime API Key in Dots Settings and start Tunnel. A new Tunnel ID is not required. The user confirmed that the connection and restart recovery worked after re-entering the key.
