# DSH Dots 2.0.1-test.2：在设置页连接官方隧道

[返回介绍](../../README.md) · [上一版功能与实机展示](v2.0.0.md)

## 更新内容

在「设置 → Dots」中完成官方 tunnel-client 的下载、安装和使用。安装位置默认跟随 DSH 当前 profile，可填写自己的目录，Desktop 提供原生目录选择；已下载的客户端可直接填写可执行文件路径。

填入 Tunnel ID 和 Runtime API Key 后，点击「启动隧道」。插件将当前 MCP 地址传入官方配置；不需要手工编辑命令。运行密钥通过子进程环境传递，保留在当前 DSH 运行内；安装目录和 Tunnel ID 持久保存。

「客户端运行中」表示进程已启动。「刷新隧道状态」调用官方客户端健康检查，单独报告连接是否就绪。「检查配置」显示官方 doctor 的诊断结果。下载、诊断或启动进行中仍可使用停止按钮。关闭 MCP 或卸载 Dots 时，只停止本插件启动的客户端及其子进程，已交给 DSH 的会话任务继续执行。

下载保留官方归档中的客户端、配套文件与许可，并核对官方 SHA-256。默认不下载、不启动；安装和启动由用户在界面点击执行。

## 安装与首次使用

在 DSH 插件添加框填写：

```text
github:Tests4gptplay/dsh-dots#2.0.1-test.2
```

打开设置中的 Tunnel 创建页面，填入名称、描述并选择自己的组织与工作区。个人连接按指南保持 Restrict client network access 未勾选；组织配置遵循管理员要求。复制 Tunnel ID，在插件内完成客户端安装及启动，再到 ChatGPT 注册 Tunnel 连接。完整步骤见 [项目介绍](../../README.md#连接自己的-dot)。

## 验证方法与结果

本地 Linux / Node 22：122 项源码和回归检查通过。真实 DSH Web 0.2.2-rc.1 / Node 24：26 项原生检查通过，包含新隧道设置接口、MCP 工具、文件、图片、取消和启停恢复。

官方 tunnel-client v0.0.20 的原始二进制参与测试：完整归档解包与校验、实际 init 配置生成、进程运行、MCP 请求转发、官方 health 读取、停止及重新启动均通过。此项使用本地受控服务模拟 OpenAI 排队接口，MCP 服务和官方客户端均实际执行；真实 OpenAI 账户连接另按用户的 Tunnel ID 和运行密钥验证。

测试脚本：`tests/tunnel.test.mjs`、`tests/tunnel-settings.test.mjs`、`tests/tunnel-official.test.mjs`。真实 DSH 集成沿用 `tests/native/verify.mjs`。
