# DSH Dots 2.0.1-test.6：MCP 与官方隧道生命周期修复

[项目说明](../../README.md) · [上一测试版](v2.0.1-test.5.md)

## 修复

### 卸载清理

卸载 Dots 时，依次注销本插件的 Tunnel 设置接口、MCP 设置接口，停止已启动的官方隧道客户端，并释放本插件的 MCP Server、DSH Peer。即使其中某个清理操作失败，其他操作仍会执行，错误按实际情况返回。已交给 DSH 的会话任务保持原有生命周期。

### MCP 密钥轮换

用户主动更换 MCP 连接密钥时，如果隧道原先正在运行，则先停止旧通道，生成并保存新 MCP 地址，再用新的地址调用官方 `tunnel-client init` 与 `run` 恢复隧道。原本停止的隧道不会被无故唤醒；自动连接失败时保留具体错误。

### 客户端更新和诊断

- 官方客户端的健康检查使用**正在运行的可执行文件**，避免安装更新后的路径与旧运行进程不一致。
- 在官方隧道客户端自行退出时，执行既有的旧目录清理，只保留当前客户端和一份旧版；用户指定的外部客户端文件不受此清理影响。
- 保留用户显式点击「启动隧道」切换新客户端的设计，以及 GitHub 最新 Release + SHA-256 校验下载方式。

## MCP 事件接口口径

`dsh_api_subscribe` 是**单次工具调用中的连续事件转发**，利用 MCP `notifications/progress` 传输 DSH 原生事件，适用于支持该机制的 MCP 客户端。它不会自动创建 ChatGPT Dot 后台事件任务。

ChatGPT Dot 的官方事件触发集成使用 [MCP Events](https://developers.openai.com/plugins/build/mcp-events) 的 Webhook 模式：`events/list`、`events/subscribe`、`events/unsubscribe`、回调验证和签名投递。这是独立协议；本版保留请求内流功能，并准确区分两者。
