## 设计与实现

真实 ChatGPT Dot → 官方自定义 MCP → dsh-dots 适配 → DSH 原生执行系统。

MCP 与 WebView 独立；首次安装默认关闭，与 v1.0.12 的登录保持处于同一 Dots 设置页。启用状态、端口和连接地址按 DSH profile 持久化。关闭释放 MCP 监听与连接资源，已提交的会话任务由 DSH 继续管理。

- `src/mcp-server.mjs`：官方 MCP SDK、HTTP 入口、工具注册、结构化结果及图片呈现。
- `src/mcp-adapter.mjs`：16 个工具；原生 Typert Gateway、SessionController 和 Tools 适配。
- `src/mcp-control.mjs`：profile 设置、启停、连接密钥、官方指南、本地工具发现检查和最近调用状态。
- `src/mcp-settings.js`：同页开关、连接参数、地址复制、完整接入步骤及官方链接。
- `src/host.mjs` / `src/client.js`：接入现有插件生命周期与设置，保留登录保持和网页入口。
- `scripts/build.mjs`：生成生产入口，打包 MCP 依赖并生成第三方许可。

执行事实来自 DSH。MCP 不保存第二份任务状态，不创建另一套调度器。对原生 API 使用运行时反射的参数名、JSON Schema 和授权入口，工具经原生 executor 执行。ChatCMD 用作方案参考，本次没有复制其 Rust 运行时或执行实现。

### 真实 DSH 与浏览器

Linux、Node 24.22.2、DSH 0.2.2-rc.1，安装候选 TGZ 后执行 20 项原生验收。覆盖默认关闭、16 个 MCP 工具发现、原生会话创建和查询、API 反射调用、文件写入/读回、图片返回、错误传递、取消、启停与整个宿主重启后的状态及会话恢复。

测试宿主发现 144 个原生 API、30 个命名空间、31 个会话工具，这些数量为该测试 profile 的观测值。

真实 Chromium 操作 DSH 设置页，验证开关启停、实际本地工具发现、连接地址遮罩、4 个官方指南入口和刷新后的关闭状态；浏览器 `pageErrors` 为零。截图来自实际运行的 DSH Web 界面。

### 当前 AI 接入与任务延续

当前 ChatGPT 助手通过测试工作区中的临时 OpenAI-completions 传输桥，逐次读取真实 DSH 模型请求并返回工具选择和回复。桥接只负责传输，不预写模型决策；DSH 执行真实文件工具并保存会话。

第一轮完成 `read → write → read`，从实际 CSV 得到小计 96、240、138，总额 474，写入并核对 report.txt。第二轮在同一会话追加指令，完成 `read → write → read`，加入数量合计 20。第二轮执行期间关闭 MCP；任务照常完成，重新开启并连接后通过原生 wait 取回完成结果。另验证模型请求执行中的显式取消，原生状态从 running 回到 idle。

详见 `2.0.0-evidence.json` 和 `2.0.0-live-model.json`。测试完成后，临时 DSH、模型传输桥和控制服务均已停止。

## 复现

```sh
npm ci --legacy-peer-deps
npm test
npm run pack:check
npm pack --ignore-scripts
```

`tests/native/verify.mjs` 使用真实 DSH Web profile 和已解包的候选插件。将 `DSH_NATIVE_ROOT` 指向隔离安装 `@deepseek-ai/dsh` 的目录；设置 `DSH_BROWSER_TEST=1` 可加入 Chromium 验收。脚本只操作自身创建的 profile/workspace，并在结束后停止宿主、清理测试 profile。
