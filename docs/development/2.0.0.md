# DSH Dots 2.0.0 开发交接

## 设计

真实 ChatGPT Dot → 官方自定义 MCP → dsh-dots 适配 → DSH 原生执行系统。

MCP 与 WebView 独立；默认关闭，与 v1.0.12 的登录保持处于同一设置页。启用状态、端口和连接地址按 DSH profile 持久化。关闭释放 MCP 监听与连接资源，DSH 会话仍由宿主管理。

## 代码

- `src/mcp-server.mjs`：官方 MCP SDK、HTTP 入口、工具注册、结构化结果及图片呈现。
- `src/mcp-adapter.mjs`：16 个工具；原生 Typert Gateway、SessionController 和 Tools 适配。
- `src/mcp-control.mjs`：profile 设置、启停、地址密钥、官方指南、本地工具发现检查和最近调用状态。
- `src/mcp-settings.js`：同页开关、连接参数、复制、指南与状态。
- `src/host.mjs` / `src/client.js`：接入现有插件生命周期与设置。
- `scripts/build.mjs`：生成生产入口并打包 MCP 依赖，生成第三方许可文件。

执行事实来自 DSH。MCP 不保存第二份任务状态，不创建另一套调度器。对 DSH 原生 API 使用运行时反射的参数名、JSON Schema 和授权入口。DSH Tools 经原生 executor 执行。插件不调用 Codex CLI，不读取 ChatGPT 登录凭据。

## 开发与验证

```sh
npm ci --legacy-peer-deps
npm test
npm run pack:check
npm pack --ignore-scripts
```

构建依赖为开发依赖，MCP 协议代码已打包在发行物内。生产安装包使用 17 文件白名单，包含源码对应的编译输出和许可；测试、开发脚本与参考宿主均不进入安装包。

`tests/native/verify.mjs` 使用真实 DSH Web profile 和已解包安装的插件执行原生验收。将 `DSH_NATIVE_ROOT` 指向隔离安装 `@deepseek-ai/dsh` 的目录，再运行该脚本；`DSH_BROWSER_TEST=1` 增加真实 Chromium 设置页验收。它只操作自己创建的测试 profile/workspace。

本轮测试运行于 Linux、Node 24.22.2、DSH 0.2.2-rc.1。当前 ChatGPT 对话通过测试工作区中的临时 OpenAI-compatible relay 实际处理了 DSH 模型请求，完成文件工具轮次和会话续写；该桥接不属于生产插件。真实 ChatGPT Dot 注册、用户手机远程连接和用户 Windows Desktop 升级为独立验收阶段。

当前容器缺少 DSH 的 workspace-write 命令沙箱，原生命令请求返回宿主错误，MCP 正确传播错误；文件工具与会话链已实际执行。未修改用户电脑、登录信息、main、Release 或市场提交。
